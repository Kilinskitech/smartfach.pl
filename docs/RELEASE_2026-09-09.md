## 2. Zmienne i publikacja testowa

- W Vercel dodaj `CRON_SECRET` jako Secret: co najmniej 32 losowe znaki wygenerowane
  przez menedżer haseł. Bez `NEXT_PUBLIC_`, bez wklejania sekretu do rozmowy.
- Production uruchamia codzienny Cron o 02:15 UTC przez `vercel.json`.
  Preview nie wykonuje harmonogramu: czyść techniczne kopie ręcznie poleceniem
  `select public.purge_ai_response_bodies();` albo utrzymuj krótkotrwałe dane testowe.
- Nie zmieniaj obecnych kluczy Stripe na Live podczas tej operacji.
- Dopiero po migracji wypchnij przygotowany commit do gałęzi `preview` i sprawdź
  wdrożenie. Po zaakceptowanych testach wykonaj merge preview → main.
- Zweryfikuj build, `/admin#operacje`, odpowiedź Cron oraz rejestrację.
- Rezerwacje starsze niż 2 minuty są do sprawdzenia przez admina. Nie kasuj tabel
  ani receiptów, aby odblokować zapytanie; użyj audytowanej akcji w panelu.

## 3. Oddzielenie Preview od prawdziwej sprzedaży

Wspólna baza i klucze Sandbox są dopuszczone wyłącznie przejściowo, gdy tabela
deployment_identity jest pusta i nie używamy Stripe Live. Nowy kod świadomie
blokuje Live bez powiązania bazy z Production.

Najprostszy bezpieczny start: dotychczasowe testowe konta i Stripe Sandbox zostają
w środowisku Preview, a sprzedaż dostaje osobny projekt Supabase. Przenieś schemat,
nie testowe rekordy klientów/subskrypcji Stripe. Jeśli chcesz użyć dotychczasowej
bazy jako Production, najpierw trzeba oddzielnie uzgodnić zachowanie/usunięcie kont
testowych i powiązań `cus_`/`sub_` z Sandbox. Nie mieszaj ich z kluczami Live.

W docelowej bazie produkcyjnej, po sprawdzeniu projektu:

```sql
insert into public.deployment_identity(id, environment)
values (true, 'production');
```

W osobnej bazie testowej:

```sql
insert into public.deployment_identity(id, environment)
values (true, 'preview');
```

Nie wykonuj obu poleceń w jednym projekcie. Jeżeli rekord już istnieje, sprawdź
go; nie nadpisuj w ciemno. Po przypisaniu bazy Production stary Preview wskazujący
tę bazę zostanie zablokowany — to oczekiwane zabezpieczenie.

W Vercel rozdziel wartości per środowisko: URL i dwa klucze Supabase, adres
aplikacji, UUID administratora, Stripe secret, ceny i webhook secret. Nowy projekt
Supabase wymaga ponownego ustawienia SMTP Auth, polskich szablonów, Site URL,
dozwolonych callbacków i rejestracji administratora. Nie wyłączaj potwierdzania e-maila.

## 4. Test akceptacyjny przed reklamą

Na dwóch własnych kontach testowych i Stripe Sandbox:

1. Rejestracja Lite oraz Pro → Checkout z 3 dniami → zapis karty → powrót.
   Bez potwierdzenia e-maila brak dostępu do AI. Po potwierdzeniu dostęp działa.
2. Nowy czat: krótki tekst (Nano), start biznesu (Luna), zdjęcie (Luna).
   Sprawdź model faktycznie użyty, koszt i źródła w OpenRouter. HTTP 200 z fallbacku
   NIE dowodzi sprawności OpenAI. Jeśli nadal 404, sprawdź raw error w OpenRouter
   i dostępne endpointy z ZDR; nie wyłączaj ochrony prywatności w ciemno.
3. Przerwij połączenie po wysłaniu i ponów identyczną wiadomość w tym samym widoku.
   Ten sam klucz daje najwyżej jedną zaakceptowaną generację i jedno naliczenie.
   Zmieniona wiadomość/odświeżenie tworzy nowy klucz. Rezerwacje niepewne są widoczne
   w panelu. Sprawdź także dwa okna wysyłające jednocześnie.
4. `checkout.session.completed` oraz aktualizacje subskrypcji finalnie zwracają 200.
   Ponów to samo zdarzenie; saldo nie rośnie i nie zeruje się ponownie. Powrót ze
   Stripe i webhook równocześnie mogą dać chwilowe 503; ponowienie musi zakończyć się sukcesem.
5. Kup zwiększenie limitu → zapas dodaje się raz → ponów webhook → zapas bez zmian.
   Zbliż się do limitu; brak dalszych generacji po wyczerpaniu puli.
6. Anuluj próbę, doprowadź ją do końca testowym zegarem/trybem Stripe, kup ponownie:
   nie ma kolejnych darmowych 3 dni, Checkout pokazuje opłatę od dziś. Na aktywnym
   abonamencie dodatkowy Checkout jest blokowany; portal pozwala zarządzać płatnością.
7. Sprawdź odnowienie, nieudaną płatność i zakończenie subskrypcji. Zdarzenie starej
   subskrypcji nie może nadpisać nowszej. Nieopłacone konto nie wykonuje AI.
8. Konto A nie odczytuje danych B przez przeglądarkę/API. Zwykły użytkownik nie
   wchodzi do admina i nie wywołuje nowych funkcji rozliczeniowych w Supabase.
9. Dochodzą osobno e-maile potwierdzenia konta, resetu hasła i umowy. Załącznik
   umowy zgadza się z zakupem. E-mail nie zastępuje sprawdzenia webhooka.
10. Fizyczny iPhone/Safari i Android/Chrome: menu, checkout, powrót, instalacja PWA,
    wylogowanie/logowanie oraz instrukcja otwarcia poza przeglądarką Facebooka.
11. Panel liczy nowe etapy i pełny koszt, również po ponad 1000 zdarzeń. Wynik
    porównaj z OpenRouter; niepewne/odrzucone generacje mogą wymagać ręcznego uzgodnienia.
12. Sprawdź eksport, odstąpienie, kontakt, anulowanie i odtworzenie kopii bazy.

Zapisuj datę, konto testowe (bez haseł), ID zamówienia/generacji i wynik. Nie
publikuj promptów i danych klientów w publicznych issues ani zrzutach.
